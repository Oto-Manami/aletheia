# @aletheia/bot

Discord サーバー「王都愛実」の Bot。入口チャンネルへの投稿から取り込みの下書きを作り、承認カードを出し、リアクションで承認・却下・保留する（設計書 docs/discord.md）。Discord の中身は読むだけで、投稿するのは承認カード・受け付けの印・返信だけ。

## 準備

1. Discord の開発者ポータルで Bot を作り、**Message Content Intent** を有効にする
2. サーバーに招待する（必要な権限: メッセージを読む・送る・リアクションを付ける・履歴を読む）
3. `.env` に設定を書く（`.env.example` を参照）
4. 仮の出典として使う情報源 `other:discord` を、データベースの `channels` に登録しておく
5. API（apps/api）を起動してから、Bot を起動する

```sh
pnpm --filter @aletheia/api dev
pnpm --filter @aletheia/bot dev
```

## 動き

| いつ                           | Bot がすること                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------------- |
| 入口チャンネルに投稿があった   | 投稿者がリアクション（💰👥🔒）を付ける時間を待ってから（既定 30 秒）、下書きを作る |
| 下書きを作れた                 | `review` に承認カードを出し、元の投稿に ✅ を付ける                                |
| 同じ投稿の下書きが既にある     | 元の投稿に 🔁 を付ける                                                             |
| 投稿のルールに合わない         | 元の投稿に ⚠️ を付け、理由を返信する                                               |
| 承認カードに ✅ ❌ ⏸️ が付いた | 登録した運営者なら、承認・却下・保留する。運営者でなければリアクションを外す       |

## 出典の判定

URL がどの情報源のどの投稿かは、Bot には書かず、情報源の設定（`channels.config.url_patterns`）で判定する（API の `/resolve`）。新しい情報源は、データベースに 1 行足せば使える。

```json
{ "url_patterns": ["^https://(x|twitter)\\.com/example/status/(?<id>\\d+)"] }
```

URL の無い投稿（雑誌のスキャンなど）は、チャンネルの設定に `fallback_channel` があれば、Discord のメッセージを仮の出典として承認待ちに出す。

## 入口チャンネルの設定

`config/intake-channels.json` に、チャンネル名ごとの下書きの初期値（公開区分・有料かどうか・仮の出典）を持つ。初期値は承認のときに人が確かめる。

## まだ無いもの

- URL からのタイトル・日付・発信者の取得
- 承認待ちの滞留などの通知（`status`）
