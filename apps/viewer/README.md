# 閲覧サイト（apps/viewer）

招待した利用者が、アーカイブを見る・探す場所。参加者は、取り込みの下書きの振り分け・確認・承認と、出来事の記録もここで行う（設計書 決定記録 0010・0026・0027）。

| 画面          | 内容                                                                                                                                                                           | 使える人 |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- |
| `/intake`     | 下書きの一覧（承認待ち・保留・承認済み・却下）。承認済み・却下は判断した人と日時つき                                                                                           | 参加者   |
| `/intake/:id` | 下書きの確認・修正と、承認・保留・却下。Discord の承認カードの「編集」から開く                                                                                                 | 参加者   |
| `/triage`     | 振り分け（残す・言及なし）。公式サイトのニュースは「出来事にする」で、その場で作った出来事に出典として紐付けて保存する（承認に回さない）。「言及なし」「関係なし」は管理者だけ | 参加者   |
| `/events`     | 出来事の一覧（日付の新しい順。題名・作品名で探す、種類で絞る。出典の無いものが分かる）                                                                                         | 参加者   |
| `/events/new` | 出来事を作る。作品・会場・出演者はその場で作れる。`?parent=<ID>` で親の出来事を選んだ状態                                                                                      | 参加者   |
| `/events/:id` | 出来事を直す（出演の状態・出典など）。何も紐付いていない出来事は、管理者と作った本人が消せる                                                                                   | 参加者   |
| `/search`     | 言葉で探す（本文・キャプション・誌面の文字・書き起こし）                                                                                                                       | 利用者   |
| `/posts/:id`  | 投稿の素材を元の順番で見る。誌面はページ番号つき                                                                                                                               | 利用者   |

- ログインは Discord のアカウント。運営者が Discord のユーザー ID を登録した人だけが読める
- 読み取りはデータベースから、ログインした利用者の権限のまま（行レベルセキュリティが見える範囲を決める）
- 承認・出来事の記録などの書き込みは API を呼ぶ。API が参加者かどうかと、管理者だけの操作かを確かめる
- サーバーを持たない静的なサイト。置き場所の設定は `vercel.json`

## 動かす

```sh
cp apps/viewer/.env.example apps/viewer/.env   # 値を入れる
pnpm --filter @aletheia/viewer dev             # 本番と同じ作り（Supabase と API が必要）
pnpm --filter @aletheia/viewer dev:demo        # 架空のデータで動くデモ版（何も要らない）
pnpm --filter @aletheia/viewer build:demo      # デモ版を 1 つの HTML にまとめる（dist-demo/index.html）
```

デモ版の人物・情報源・発言はすべて架空のもの。操作はその画面の中だけで反映され、どこにも送らない。

## まだできないこと

- 画像・動画そのものの表示（ファイルは Drive にあり、API がファイルを返せるようになってから）。それまでは、運営者は「保存先で開く」から Drive で開く
